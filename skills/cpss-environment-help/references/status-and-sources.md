# Status and Source Rules

Use these distinctions consistently when explaining the configured environment.

## Status

- **Observed active**: verified now through the current environment or tool state.
- **Documented target**: explicitly selected for the desired clean environment.
- **Planned**: proposed and intentionally retained as future work, but not implemented.
- **Historical**: previously existed or was discussed, but current deployment is not established.
- **Unknown**: available evidence is insufficient.

## Evidence rules

- A conversation describing an automation is not proof that the automation exists.
- A Skill named in an architecture document is not proof that the Skill is installed.
- A repository containing Skill source is not proof that the Skill is installed in ChatGPT.
- A Project summary is not a substitute for its exact instruction body when exact reconstruction matters.
- Memory is useful for orientation, not for claiming reproducible target state.

## Boundary rule

Help explains and navigates current/documented architecture. If answering requires deciding a new ownership model or changing the architecture, hand off to architecture governance.
